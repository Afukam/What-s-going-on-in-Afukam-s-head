# AWS Cowrie Honeypot + Wazuh SIEM Lab

_Status: In progress · Last updated: 2026-11-26_

## Overview

This project is a defensive security homelab built in AWS. It uses **Cowrie**, an SSH/Telnet honeypot, to capture activity directed at a simulated service, and **Wazuh** as the security monitoring platform for collecting and investigating endpoint telemetry.

The aim is to build an end-to-end learning environment for security operations: deploy the infrastructure safely, collect useful telemetry, create detections, investigate activity, and document the results.

> This is a learning lab, not a production security service. The honeypot is not being presented as publicly exposed to the internet. Any future internet-facing testing will be a separately planned phase with explicit network restrictions and monitoring.

## Objectives

- Deploy and configure a Cowrie SSH honeypot on an AWS Linux instance.
- Deploy a separate Wazuh environment and onboard an agent.
- Establish and verify the telemetry path from the honeypot environment into Wazuh.
- Build dashboards and detections for authentication attempts and suspicious SSH activity.
- Investigate observed events and document findings using MITRE ATT&CK where appropriate.
- Review network controls and operational costs before any broader exposure.

### Phase 1 — AWS foundation and Cowrie deployment

**Completed**

- Provisioned the AWS environment for the honeypot.
- Set up the Ubuntu host and a dedicated Cowrie service account.
- Installed and configured Cowrie.
- Confirmed Cowrie was listening on its configured SSH honeypot port.

### Phase 2 — Cowrie configuration and controlled SSH testing

**Completed**

- Confirmed the Cowrie SSH listener was active.
- Tested a local SSH connection to the honeypot.
- Tested a controlled connection from the Mac client.
- Located and reviewed Cowrie JSON event logs.
- Identified session and command-input events generated by the tests.

These were controlled tests from the project owner's own client. They should not be described as unsolicited external attacker activity.

### Phase 3 — Wazuh deployment and agent onboarding

**In progress**

- Created the separate Wazuh environment in AWS.
- Established access to the Wazuh dashboard.
- Confirmed that an agent was running in the environment.

**Still to verify:** that the correct agent is reporting to the intended manager, that Cowrie log files are being collected, and that Cowrie events can be searched and interpreted in Wazuh.
